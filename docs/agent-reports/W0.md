| `docker/entrypoint.sh` (new), `Dockerfile:23` | Container start: preflight → `alembic upgrade head` → uvicorn. `set -eu`: any failing step stops the container |
| `app/core/preflight.py` (new) | `run_preflight()` `:24` = API-key configuration check + data load. Used by the lifespan (`app/main.py:31`) and run once by the entrypoint (`python -m app.core.preflight`) |

Why the preflight exists: found during the Docker run. With `--workers 4`, a
lifespan that raises does **not** stop the container: uvicorn's supervisor
restarts the failing workers forever (the first test container stayed "Up
(unhealthy)" in a crash loop). Running the same checks once before uvicorn makes
the container exit 1 with the error.

Two names are listed commented-out in `.env.example` on purpose
(`CORTEX_API_WORKERS`, `CORTEX_REDIS_FALLBACK_ENABLED`): their unset behaviour
differs between a direct run (1 worker, fallback on) and docker compose (4
workers, fallback off), and an active line would silently change the compose
defaults for everyone who copies the file.

Decision the reviewer should look at: **with no key configured and
`APP_ENV=local`, authentication is off** (a warning is logged at startup,
`app/core/auth.py:102-112`). With any other `APP_ENV` and no key, the API refuses
to start (`:87-94`). Reason: the 576 existing tests call `/api/v1` routes with no

is not owned either. `APP_ENV` defaults to `local`, so a deployment that sets
neither `APP_ENV` nor keys runs without authentication. See open issue 2.
